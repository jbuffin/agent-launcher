# Definition of Done

SPEC §37, item by item. Each line says how the criterion is met and where the evidence is. Evidence is a test (written `tests/file.py::test_name`; `tests/test_docs.py` fails if a name here stops existing) or a command you can run. Where a criterion needs a person at a cmux terminal with the real harnesses, the gap is stated and points at [live-validation.md](live-validation.md). Nothing here is claimed on the strength of a fake alone without saying so.

Status at the V1 release-readiness check: **automated evidence on fakes (real git, the mock terminal, a fake `gh`), with the live gaps listed** per criterion below. The live gaps need the real cmux and the harnesses' real screens and only the engineer can close them. No criterion is known to fail, and none is proved on real cmux yet.

Run all of the automated evidence: `uv run pytest -q` (no cmux, no network). With `COMMODORE_LAUNCHER_LIVE=1` it also runs the sandbox-repository tests; with `COMMODORE_LAUNCHER_PACKAGING=1` the pipx install and upgrade test.

## Definition of Done, line by line

1. **The Python package installs successfully.** `tests/test_packaging.py::test_pipx_install_from_wheel_and_upgrade_keeps_config_and_state` (opt-in, `COMMODORE_LAUNCHER_PACKAGING=1`) builds the wheel, installs it with pipx into temporary directories, runs `version`, `doctor --json` and `skill path` from the installed copy. `tests/test_configure.py::test_skill_is_in_the_built_wheel` checks the bundled skill is in the wheel. Metadata: `tests/test_packaging.py::test_metadata_is_conventional_for_a_future_homebrew_formula`. The license is MIT, declared in `pyproject.toml` and shipped as `LICENSE`. Command: `T=$(mktemp -d) && uv build -q --out-dir $T/dist && PIPX_HOME=$T/home PIPX_BIN_DIR=$T/bin PIPX_MAN_DIR=$T/man pipx install $T/dist/*.whl && $T/bin/commodore-launcher version`. Gap: installed on one macOS machine with Python 3.14; other Python versions (3.11 to 3.13) are declared but not run here. `pipx upgrade` from an index or a git spec is not exercised: the upgrade test uses `pipx install --force` of a newer wheel.
2. **First-run setup works.** `tests/test_wizard.py::test_answers_file_writes_config_and_is_idempotent`, `tests/test_setup_cli.py::test_setup_with_answers_and_yes`, `tests/test_wizard.py::test_rerun_never_removes_existing_config`, and the first step of `tests/test_scenarios.py::test_scenario_j_gh_dash_bootstrap`. ## The ultimate success criterion

"A developer can select a GitHub issue or PR, choose a harness, and begin working in an isolated, correctly configured, resumable session with minimal interaction." The path is `commodore open <url>` (or the gh-dash shortcut): proved end to end on the mock terminal by scenario A, and against real GitHub by the live tests. Doing it on real cmux with real harnesses is exactly what [live-validation.md](live-validation.md) is for; that is the one remaining acceptance step, and it belongs to the engineer.

## Known gaps, in one list

- Real cmux and the three harnesses' real screens: [live-validation.md](live-validation.md) §2 to §10.
- `npx skills add` from GitHub, and the gh-dash key in a running gh-dash.
- A fork PR or a PR by someone else on real GitHub (one account).
- Python 3.11 to 3.13 and Linux are declared (`requires-python`, classifiers) but not run.
