# Definition of Done

SPEC §37, item by item. Each line says how the criterion is met and where the evidence is. Evidence is a test (written `tests/file.py::test_name`; `tests/test_docs.py` fails if a name here stops existing) or a command you can run. Where a criterion needs a person at a cmux terminal with the real agents, the gap is stated and points at [live-validation.md](live-validation.md). Nothing here is claimed on the strength of a fake alone without saying so.

Status at the V1 release-readiness check: **automated evidence on fakes (real git, the mock terminal, a fake `gh`), with the live gaps listed** per criterion below. The live gaps need the real cmux and the agents' real screens and only the engineer can close them. No criterion is known to fail, and none is proved on real cmux yet.

Run all of the automated evidence: `uv run pytest -q` (no cmux, no network). With `AGENT_LAUNCHER_LIVE=1` it also runs the sandbox-repository tests; with `AGENT_LAUNCHER_PACKAGING=1` the pipx install and upgrade test.

## Definition of Done, line by line

1. **The Python package installs successfully.** `tests/test_packaging.py::test_pipx_install_from_wheel_and_upgrade_keeps_config_and_state` (opt-in, `AGENT_LAUNCHER_PACKAGING=1`) builds the wheel, installs it with pipx into temporary directories, runs `version`, `doctor --json` and `skill path` from the installed copy. `tests/test_configure.py::test_skill_is_in_the_built_wheel` checks the bundled skill is in the wheel. Metadata: `tests/test_packaging.py::test_metadata_is_conventional_for_a_future_homebrew_formula`. The license is MIT, declared in `pyproject.toml` and shipped as `LICENSE`. Command: `T=$(mktemp -d) && uv build -q --out-dir $T/dist && PIPX_HOME=$T/home PIPX_BIN_DIR=$T/bin PIPX_MAN_DIR=$T/man pipx install $T/dist/*.whl && $T/bin/agent-launcher version`. Gap: installed on one macOS machine with Python 3.14; other Python versions (3.11 to 3.13) are declared but not run here. `pipx upgrade` from an index or a git spec is not exercised: the upgrade test uses `pipx install --force` of a newer wheel.

## The ultimate success criterion

"A developer can select a GitHub issue or PR, choose an agent, and begin working in an isolated, correctly configured, resumable session with minimal interaction." The path is `agent-launcher open <url>` (or the gh-dash shortcut): proved end to end on the mock terminal by scenario A, and against real GitHub by the live tests. Doing it on real cmux with real agents is exactly what [live-validation.md](live-validation.md) is for; that is the one remaining acceptance step, and it belongs to the engineer.
